# Separate Django forms into focused modules

Use this prompt when a Django app has a large forms file and the user wants it reorganized into smaller, domain-based modules.

## Goal
Refactor forms into separate files or modules while preserving all existing behavior, validation, and imports.

## Instructions
1. Identify the logical form groupings by model or feature area.
2. Move related form classes, helper constants, and validation logic into focused modules.
3. Keep the public form names the same unless the user explicitly requests a rename.
4. Preserve field definitions, widget configuration, validation rules, and form behavior.
5. Update imports so existing views, tests, and other code continue to work.
6. If the project uses a package structure, export the forms from the appropriate package entry point.
7. Prefer minimal, safe refactors over large rewrites.
8. If a form is shared across multiple features, keep it in a common module and document the reason.

## Expected output
- A short summary of the refactor, including which files were created or updated.
- Confirmation that behavior and validation were preserved.
- Any follow-up recommendations for naming, module layout, or import cleanup.

## Repository-specific guidance
For this repository, treat the existing forms module as a candidate for splitting by domain, such as car, garage, job, and report forms. Keep the Django app structure consistent and avoid breaking the current workflow.
